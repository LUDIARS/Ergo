## 受け入れ条件 (契約書式)

- C-1 breed(input): 同じ親・体数・強さ・重み・seed なら同じ子、seed が違えば違う子 — `breed: same seed gives the same children…`
- C-2 mutate(genome, strength, bias, rng): 強さ 0 なら変化なし、遺伝子は 0..1 に収まり、離散遺伝子の反転は低確率 (上限 0.25)、重みの符号の向きに平均がずれる — `mutate: *`
- C-3 crossover(a, b, rng): 各遺伝子はどちらかの親の値で、両親が寄与する。親 2 体以上なら子ごとに相異なる 2 親 — `crossover: *`、`breed: two or more parents…`
- C-4 decode(genome, carrier, name): 共有表の値域 (= sanitize と同じ) に収まり、min ≤ max、`maxAlive` は整数、positionShape / svgSource / svgScale は親のまま — `decode *`、`positionShape / svgSource / svgScale…`、`breed: the first parent's svg fields…`
- C-5 runGeneration(req, advisor): 方向が無ければ LLM を呼ばない。重みは子をその向きへずらす。LLM が使えない / 失敗しても子は出て、`direction.status` が理由を示す — `no direction…`、`direction weights shift…`、`LLM unavailable…`、`LLM failure…`、`makeAdvisor never throws…`
- C-6 routes: `POST /api/generation` が子を返し、壊れた本文に 400、`GET /api/seeds` が既定 + カタログ — `routes: *`
- C-7 sanitizePresets: 値域を共有表へ移した後も、丸めの上下限と既定値が変わらない — `tests/vfx-suggest/sanitize.test.ts`
- C-8 build: `npm run build` (tsc) が通る

Augur の契約 (`augur.contracts.json` と述語モジュール) は今回入れない。Ergo の tools/ergo には Augur の契約ランタイムを
入れていないため、上の受入条件は node:test のテスト名で裏づける。

## 再利用探索の採否

| 候補 | 採否 | 理由 |
|---|---|---|
| `particle/schema.ts` の `ParticleEffectConfig` / `DEFAULT_EFFECT` / `mergeConfig` | 採用 | schema の正本。部分 JSON は `mergeConfig` で既定値と合わせる |
| `vfx-suggest/sanitize.ts` の値域 | 採用 (共有表へ切り出し) | 値域を `particle/ranges.ts` に出し、sanitize と vfx-breed が同じ表を読む。sanitize の結果は変えない (C-7) |
| `vfx-suggest/sanitize.ts` の `extractJson` | 採用 | LLM 応答から JSON を取り出す処理をそのまま使う |
| `vfx-suggest` の `VfxGenerator` (`makeGenerator`) | 不採用 (バックエンドの選び方と起動部品は踏襲) | 型がプリセット生成専用 (`generate(req: GenRequest)` → `VfxPreset[]`) で、重みを答えさせる問いを載せられない。改修は既存プラグインの変更になるので、同じ env (`ERGO_VFX_BACKEND` / `ERGO_VFX_MODEL` / `CLAUDE_BIN` / `ANTHROPIC_API_KEY`) と同じ起動部品 (`@ludiars/one-shot` / Anthropic SDK) を使う advisor を別に持つ。また vfx-suggest と違い、設定が誤っていても例外を投げず「方向指示なし」にする |
| `vfx-suggest/catalog.ts` の `CATALOG` | 採用 | 起点 (`GET /api/seeds`) に使う |
| `vfx-suggest` の `POST /api/ks-emitter` | 採用 | 書き出しの変換はサーバ側の ks_export を正本のまま呼ぶ (UI に変換を持たない) |
| particle エディタ UI の描画 (`particle/ui/index.html` の emit / step / draw) | 採用 (ES module に切り出し) | 埋め込みのスクリプトで全体変数 `cfg` に結びついているため、同じ計算を `particle/ui/preview.js` にまとめた。particle エディタ自体は変えていない (挙動を保つため)。エディタ側を同じ部品に寄せるのは別作業 |
| Figmentum の breed-sound | 方針のみ採用 | 「適応度は人間の目、自動指標を持たない」の考え方。コードは別言語・別ドメインなので使わない |
